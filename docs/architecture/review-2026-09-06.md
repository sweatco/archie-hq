# Architecture review — 2026-09-06

**TL;DR:** Keep the task-centered runtime, file persistence, and opt-in runner boundary. Fix ownership, filesystem, and lifecycle failures within those boundaries. Configuration schemas now own their TypeScript types; repeated protocol checks and long source explanations are reduced. This is a focused source review and regression pass, not a complete security audit.

## Scope and architecture

Reviewed from commit `5b695f7`, emphasizing the recently added runners and their task, agent, and sandbox integration. The repository-wide test suite also covers existing connectors, approvals, persistence, and recovery; those modules were not all reviewed line by line.

```text
Slack / GitHub / API → Task → Agent → SDK tools
                        │             └→ runner tools → RunnerManager → Orchard → Tart
                        └→ task files                      └→ lease files / exec logs
```

| Boundary | Assessment and source |
| --- | --- |
| Task lifecycle | `tasks/task.ts` owns task state and completion. Runner cleanup is called on completion, while pauses preserve leases. Keep one lifecycle owner. |
| Runner policy | `runners/manager.ts` owns identity, allowlists, capacity, and cleanup. `config.ts` validates operator policy and now defines its inferred types. |
| Remote execution | `execution.ts` owns durable commands and deadlines; `orchard-provider.ts` owns transport. Keep the provider contract: it is a useful replacement/test boundary, despite having one production implementation. |
| File transfer | Local clones remain canonical. `workspace.ts` stages remote snapshots and routes collected artifacts; `transfer.ts` validates paths and archives. |
| Persistence and traceability | Task metadata, lease JSON, command JSONL, and events expose state without requiring a database or separate control service. Delivery cursors and provider acknowledgements represent different states and must remain separate. |
| Ejectability | Omitting runner configuration removes its tools and initialization. Repository-specific Xcode/debug workflows remain outside runtime orchestration. Drain existing leases before disabling the controller: disabling it also stops its reaper. |

## Defects fixed

| Trigger and prior failure | Result | Regression evidence |
| --- | --- | --- |
| Workspace symlink targets a host file, protected file, or missing external write target; hooks accepted its apparent workspace path. | Resolve symlinks and `..` in filesystem order; check actual read/write roots and protected aliases. | `agents/__tests__/sandbox.test.ts`: escaping links, dangling writes, protected aliases, declared skill access. |
| A tracked directory is replaced by a symlink before snapshotting. | Reject files reached through directory symlinks instead of archiving host content. | `runners/__tests__/transfer.test.ts`: tracked directory replacement. |
| A repository filename starts with `@`; tar treats it as archive inclusion syntax. | Prefix archive inputs with `./` so filenames stay literal. | `transfer.test.ts`: literal `@notes`. |
| Instance IDs share a prefix, or an ID ends in a dash. | Validate the entire owned backend suffix for both recovery and orphan deletion; preserve the configured identity. | `runners/__tests__/manager.test.ts`: foreign-instance recovery, orphan deletion, trailing-dash identity. |
| Recovery quarantines a corrupt state file, then an agent requests another lease. | Refuse runner operations for that task instead of overwriting its retained history. | `manager.test.ts`: quarantined task rejected while healthy recovery continues. |
| Task completes with a debug lease and a command deadline later than that lease. | Cap active command deadlines at the retained debug deadline, including startup reconciliation. | `manager.test.ts`: detached command cannot retain the completed task's VM. |
| Readiness provider throws before returning an exit event. | Close the readiness session in `finally` before another attempt. | `manager.test.ts`: failed readiness closes its remote session. |
| Clean CI install uses the checked-in lockfile. | Restore the missing `@types/ws` package record without changing dependency versions. | `npm ci`. |

New behavioral regression cases failed against the original implementation before the fixes. Existing tests remain passing.

## Simplification

- The architecture-review changes removed 175 physical lines from production TypeScript before the subsequent E2E work. Most of the reduction comes from duplicated configuration types and source comments; the security fixes add necessary logic.
- Sandbox implementation now contains the enforcement code and terse rationale. Architectural explanations and limitations live in `security.md`.
- Orchard output, error, and exit events share one watermark validation path. Queue accounting also charges a minimum amount per event, including empty output.
- No new runtime dependency, provider framework, state store, or tool protocol was added.

## Remaining constraints

- **Shared executable cache:** `buildPackageManagerCacheEnv()` grants agents a shared npm cache containing `_npx`. Its executable installations are reused without integrity verification. Separate MCP execution caches from agent-writable caches or preinstall those servers; this needs a distinct cache/deployment change.
- **API trust:** `/api` has no application authentication, including approval routes, and the HTTP server binds without a loopback-only host. Its security depends on the deployment's network/authentication perimeter. This review did not change API clients or deployment policy.
- **Filesystem races:** Hooks and snapshot checks validate paths before another component opens them. They are not atomic containment against concurrent mutation, and checking a recursive tool's starting path does not confine every later traversal. OS sandbox enforcement must be verified separately.
- **Runner ownership:** Exactly one process per workdir and instance ID remains required. Existing leases made from an ID ending in a dash need explicit upgrade reconciliation; see `runners.md`.
- **Complexity hotspots:** `tasks/task.ts`, `agents/spawn.ts`, and `agents/tools.ts` remain large. Extract cohesive responsibilities when changing those behaviors; avoid spreading the same lifecycle across more files solely to reduce individual file size.

## Follow-up: real Tart verification

The [persisted Sweatcoin scenario](../guides/sweatcoin-tart-e2e.md) subsequently verified a real native build, process liveness, binary artifact integrity, restart/retry, and VM deletion. It exposed and fixed replay-buffer overflow during artifact download and retained SSH connections after command completion. The earlier validation above describes the initial review; the runbook records the later live verification and its scope.

Repository MCP support now uses an 81-line guest client through the existing runner execution and artifact paths. The same allowlist, task lease, deadlines, and cancellation apply; no new runtime dependency or persistent proxy is required. Including this addition and the transfer fixes, production TypeScript is 35 lines smaller than the review baseline, excluding test harnesses. See [runner MCP](../guides/runner-mcp.md) for the interaction contract and session limits.
