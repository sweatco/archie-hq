# Replay evaluation pilot

`npm run replay -- components` runs the actual attention service, observation recall, and task-memory context in clean processes with recorded model decisions and fake Slack. `npm run replay -- smoke` adds a synthetic factual-preservation request through the real Task/Agent/Claude SDK lifecycle. `npm run replay -- pilot .replay/sanitized-capture.json` also includes automatically selected, supported production text requests. Runs compare the unchanged prompt with a concise deployment instruction, serially, once per case. This is a mechanics pilot; it does not establish an improvement or production accuracy.

Use Node 24 and the declared npm 11.16.0. Install normally with `npm ci`, then run `npm run replay:typecheck` and `npm test -- tools/replay/replay.test.ts tools/replay/capture.test.ts tools/replay/run.test.ts`. Evalite is pinned to 0.19.0. The pilot uses its supported in-memory storage and persists JSON/static artifacts. Its transitive native SQLite backend crashed during real SDK runs on Node 24.19.0; this path does not instantiate it and needs no native override or custom storage.

`npm run replay -- dataset EPISODES_JSON` runs a bounded portable episode array using the same adapter, scorers and report. Keep expectations in that parent-side file; only `input` reaches the worker. Before fresh SDK runs, `npx tsx tools/replay/isolation-check.ts` checks the SDK's actual init catalog contains no native tools using the worker's shared empty-tool configuration, then requires an actual denied MCP marker attempt with no marker created. It fails clearly when inference credentials are unavailable; a component pass cannot replace that live check.

## Capture and selection

Run `tools/replay/capture.mts FROM_ISO TO_ISO [SAMPLE<=10] [SEED]` with Node 24 at the production source, redirecting stdout to a restricted local `.replay/sanitized-capture.json`. For SSH/container capture, send the script through `docker exec -i CONTAINER node --input-type=module-typescript - FROM_ISO TO_ISO SAMPLE SEED`. The script requires the inactive current PM session's main transcript to contain the request followed by an assistant end turn, plus a later shared task-completion event. It scans SDK project transcript descendants for tool use and excludes missing, incomplete, tool-dependent or multi-turn histories. Capture accepts single-request histories using only local reply/completion operations. `ToolSearch` is allowed only when every call has exactly one successful recorded result containing exclusively those local tool references. Capture is separate from replay eligibility: the corpus admits explicit quoted transformations or anchored English/Russian presence checks (an optional reaction annotation is ignored for classification). Other contextual requests remain captured but excluded; original eligible request text is unchanged. Selection is deterministic by seed; no task IDs are chosen by hand. It exports sanitized requests, pseudonymous IDs, source hashes, dates, historical word counts and aggregate exclusions. Raw transcripts, historical answers, credentials and identity maps remain at the source. Check applicable production-data authorization before executing an export.

Names known from task authors, URLs, emails and Slack IDs (including entire mention display labels) are replaced consistently; secret-pattern requests are quarantined. This pattern sanitizer cannot classify every possible private reference. Derived captures remain private and ignored; do not commit them. The sampled cohort is deliberately narrow and biased, not a representative production sample. A separate later-window holdout and human calibration remain necessary before tuning or interpreting subjective quality. Historical answers and silence are never truth labels.

When initiative storage exists, capture uses SQLite's backup API to obtain a consistent image including committed WAL data, then exports only its hash and table counts. The database and its contents remain at the source. Missing initiative storage is reported explicitly; task recordings cannot establish ambient attention coverage. Current memory is excluded because it is not a historical starting snapshot. Missing recordings or unsupported capture formats fail or exclude the case; there is no production-tool fallback.

## Isolation and measurements

`adapter.ts` is callable independently of Evalite. Every arm gets a new process, workdir, home, temporary directory, plugin directory and secrets directory; the process is killed as a group on timeout and its state is removed. Only an explicitly supplied inference API key enters fresh SDK workers. The SDK receives no native tools, empty network domains, no external MCP servers, and Archie's existing PreToolUse deny policy on every engine server except local `post_to_user` and `report_completion`. CLI delivery is simulated locally. A production Slack request replayed this way measures response behavior only: it does not reproduce Slack ingress, historical plugins, authorization, tools or memory extraction.

Attention fixtures cover duplicate input, cancellation and revoked source access. Observation recall covers correction and access revocation. Separate task-memory fixtures create two actual Task instances, apply user-memory updates chronologically, and retrieve through the existing authorized-author/context builder for the second task. Their identity grants are fixtures; they do not test Slack's live authorization or automatic extraction. Recorded-component timings exclude inference and must not be compared with fresh SDK latency.

Verifier expectations stay in the parent; workers receive only visible episode inputs. Required facts, forbidden evidence, delivery count/audience, execution errors and missing results are independent required gates. Task requests require at least one nonempty CLI response and delivery; silent completion fails even when no identifier checks apply. Multiple valid posts are allowed. A high Evalite average cannot override a failed case. Production cases check execution and delivery only; they have no automatic factuality/usefulness label or pseudonym-echo requirement. Synthetic response fixtures retain explicit fact checks. Non-success SDK results, missing results/stop reasons and incomplete diagnostics fail execution even when Task metadata says completed and a correct response was delivered. Safe diagnostics retain only tool names, stop reasons, SDK result subtype/reported turn count and fixed diagnostic errors; raw runtime transcripts are removed with the isolated state. Broader usefulness and unsupported-claim judgments are unvalidated. If the runner fails before creating a reportable run, the parent still saves a failed completeness summary and export error, closes storage and exits nonzero; it does not manufacture a report.

Each run saves exact source-file hashes (including local edits), code revision, dataset/evaluator hashes, configuration, paired result rows, SDK usage, required gates, Evalite JSON/static report and a report-status sidecar under `.replay/`. Run history persists as files, not SQLite. Callback windows verify serial execution across variants; the suite uses the existing keyed lock because Evalite's concurrency setting alone permits variant overlap. Fresh response time starts after imports/task setup and ends after settlement; grading and report generation are excluded. `firstPostMs` is first visible output, not a validated time to useful answer. SDK costs reuse cumulative-query aggregation; absent cost stays `null`. Background extraction is disabled for CLI cases; recorded components make no model calls. Grader cost is zero because no model grader runs. The default `haiku`/`low`, four-turn, two-minute configuration is a cheap smoke configuration, not the deployment's model baseline; set `REPLAY_MODEL` explicitly before any matched product experiment.

Open the saved `report/index.html` through a static HTTP server. Static report inspection does not rerun models; Evalite serve/watch mode can rerun a suite and is unsuitable for read-only inspection. Keep all paid runs small and serial. Harbor/distributed jobs, general recorded-tool execution, production memory acquisition, representative sampling and calibrated subjective grading are outside this first pilot.

## Complete recorded sessions and code comparisons

`npm run replay -- sessions .replay/full-session-capture.json [RUNTIME_ROOT]` evaluates the current product baseline once on the whole prepared corpus. `npm run replay -- compare SNAPSHOT BASE_ROOT CANDIDATE_ROOT` compares two actual runtime checkouts using the same trusted harness, model/configuration and corpus; it does not apply the concise modifier. `npm run replay -- compare-components BASE_ROOT CANDIDATE_ROOT` separately compares the fixed attention, observation-recall and task-memory fixtures. Those are recorded component regressions, not production attention/memory measurements. The older smoke/pilot modes remain mechanics probes.

At the source, run `capture-sessions.mts FROM TO SEED MAX_SESSIONS inventory` for counts, dates, full/sample workload maxima, bytes and compressed-size estimates only. `capture` mode prepares whole eligible sessions, with a 256 KiB per-session and 16 MiB corpus bound; it fails rather than truncating a corpus beyond its explicit session limit. It requires all chronological shared inputs and recognized SDK input envelopes, one-to-one tool use/result IDs, same-session results within the same user turn, and finite input/end/settlement ordering. Unaccounted runtime notices, unsupported input blocks, overlapping requests, missing history, native/subagent/core-state work and nontext results are excluded with counts. Sample selection is deterministic by capture seed; nobody picks task IDs.

The private snapshot contains all supported user turns and recorded external MCP arguments/results/error flags. Complete local-only sessions are retained as a separate inventory cohort with empty recording segments. Known identifiers are consistently sanitized across inputs and results; historical assistant answers and local reply arguments are excluded. The pattern sanitizer is not a general privacy classifier. Raw snapshots, sanitized corpora, logs and reports remain private; public CI receives only the deliberately projected aggregate metrics described in [the CI guide](replay-ci.md).

The adapter runs the actual Task lifecycle against each selected runtime source. Between inputs it uses the existing `Task.get` reload boundary and reapplies model, turn limits and tool restrictions before spawning the resumed agent. Recorded external MCP servers have no production endpoints: even recorded mutations return only their simulated receipt. Only the current human turn's recording segment can be consumed. The parent retains future inputs, expected call arguments and recorded results outside SDK-readable state, releasing a result only after an exact tool-name/argument/order match. Missing, divergent and unconsumed recordings fail a separate completeness gate; they are replay coverage failures, not evidence that the candidate's answer is worse. A recorded error remains an error result.

Recognized historical inbound frames are preserved, including the original user body and sanitized sender/channel/time context. `Task.sendMessage` enqueues that frame directly; it does not call the Slack/API envelope builders again. The fresh task delivers only to local CLI, so this does not test Slack ingress, live authorization bindings or changes to ingress framing. No terminal memory is treated as historical starting state. Original tool schemas/descriptions were not recorded; catalogs expose neutral names and argument keys only, with no future values. Generated earlier replies may differ from the historical conversation that later human inputs assumed. Exact recording completion is not a calibrated factuality or usefulness judgment.

Each full session requires every captured user turn to execute, complete recording consumption and correct local audience for any emitted delivery. Generic recorded activity may legitimately be silent; per-turn post counts include zero without a subjective reply-necessity label. Explicit task fixtures retain their nonempty response requirement. Timings/words include the generated conversation and SDK-reported total cost remains separate from unknown background cost. `REPLAY_CONFIG` accepts explicit `model`, `effort`, `maxTurns`, `timeoutMs` and `sample`; freeze these before inference. Defaults derive larger turn/time ceilings from the workload instead of inheriting the four-turn greeting limit. Manifests record effective limits, sample, common harness source, corpus hash and both runtime revisions/file hashes. Local tooling-only edits evaluate the current baseline; they do not establish an improvement over different product code.
