# Memory evaluation

`npm run memory:eval -- <command>` runs an offline memory evaluation. It makes model calls for extraction, answering, and grading, but never contacts Slack, repositories, or business systems. Original histories, pseudonym mappings, checkpoints, answers, and reports stay under `/Users/igorsova/Projects/achie-snapshots/memory-eval/`, outside this repository. Set `ARCHIE_EVAL_HOME` for a different private location.

| Command | Effect |
| --- | --- |
| `inventory` | Verifies and extracts the pinned source archive into a temporary private directory, then counts tasks, logs, and completions. |
| `draft` or `import` | Regenerates the private corpus and source-label review sheet from the verified archive, synthetic fixtures, and cleaned LongMemEval S files. |
| `labels` | Drafts claims for Archie recall cases with Sonnet 5 under the initial budget; labels remain quarantined pending source and authorization review. |
| `validate` | Checks references, chronology, splits, scope, and evidence spans. |
| `build` | Preflights exact model IDs and builds missing routine checkpoints; `--case ID` limits it to one case. |
| `run` | Runs the bounded routine in no-memory, candidate, and oracle arms; `--case ID` runs one diagnostic case. Writes a report and independent answer-calibration packet. |
| `report` | Displays the latest or named saved run report. |

The corpus currently has 111 cases and 65 histories. It includes 40 Archie recall and future-task drafts, controlled synthetic timeline and future-task cases, and 24 cleaned LongMemEval S cases. The routine chooses six synthetic future-task cases and two public cases, one factual and one abstention. All Archie cases are quarantined because the archive lacks historical channel properties and requester authorization. They cannot enter the routine until those properties are verified at each query and completion. The real histories are useful for drafting and inspection, but a recorded memory destination is not proof of authorization. Public cases are an adaptation of the [cleaned release](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned), not an official leaderboard result.

The Archie archive SHA-256 is `eb5b2e4d66e2954979bebf41db89878bfc8a5c4b5390dfc12dcdc23ec4f24907`. `inventory` and `draft` verify that hash before extracting; `ARCHIE_EVAL_ARCHIVE` can point to an identical archive elsewhere. Original messages are parsed as multiline records. Replay preserves verified author IDs, names, and message timestamps, allowing production profile extraction to distinguish the author's own statement from a colleague's quotation. Each completion replays only the task transcript visible at that cutoff. Current memory snapshots are never gold or initial state.

## Runtime and budgets

Each checkpoint has an isolated workdir. Its key includes the visible history, cutoff, resolved memory caps and housekeeping setting, source hashes for extraction and replay, model, and pricing. Reader and grading code has a separate hash so changing it does not rebuild ingestion checkpoints. A manifest is checked before reuse. Successful completions are snapshotted; failed attempts restore the previous state before retrying. The candidate arm copies the checkpoint. No-memory has no memory tools; oracle receives only authorized cited evidence. Probes never become ingestion input.

Replay calls the production extractor, sanitizer, writers, and housekeeping through `replayTaskCompletion`. Extraction and housekeeping are both pinned to Sonnet 5 and charged to one persistent $100 initial ledger. The ledger uses a file lock and atomic replacement, validates old charges, and fails closed on corruption or exhausted capacity. Reservations with uncertain usage remain charged. The probe and Opus 5.5 judge share a $10 ledger per run. Model IDs are preflighted. `ANTHROPIC_API_KEY` comes from the environment or the main worktree `.env`; `ARCHIE_EVAL_ENV_FILE` overrides that path. Pricing assumptions are in `budget.ts` and must be checked against [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) before a later run.

Candidate authorization uses the production classification decision with offline case properties. Unknown, revoked, external, wrong-requester DM, and cross-private scopes deny access. The answer probe has at most three memory calls and a final answer turn. Fixed search and candidate context/tool traces record whether source references or factual words surfaced. Those diagnostics do not establish that the answer is correct. Canonical task-summary retention is counted separately. The retention holdout includes many same-entity updates, but it has no runtime assertion that the original entity observation was evicted; do not interpret it as a verified eviction-recovery result until that precondition is observed.

The judge sees the complete authorized original-event history, not only the oracle spans, with no silent truncation. It distinguishes unsupported, contradicted, and unverifiable answer claims. An oversized history fails grading explicitly. Answer and fixed-retrieval failures remain in the denominator; an incomplete required stage makes the run exit nonzero. Abstention success requires an appropriate refusal and a supported explanation. Reports slice results by source, workload, ability, task kind, and split, including paired outcomes, stale or leaked claims, retention/surfacing, tokens, latency, and cost. Quality remains **provisional** until independent source-label and answer calibration is finished; memory uplift is not an acceptance requirement.

Each run writes `calibration-review.md`, with actual sampled answers and complete authorized evidence, and a separate `calibration-model-verdicts.json`. A reviewer should complete the former before opening the latter, then record differences in `calibration-disagreements.md`. No human judgments are prefilled. The private `review-sheet.md` is for source labels and historical authorization. Missing attachments and external state stay quarantined. Injection-only and tools-only ablations are deferred because the present routine first needs human-calibrated quality labels; current candidate results reflect both mechanisms together.

The checked-in generator contains only synthetic fixture content. Real and public corpus instances are generated outside this repository. GroupMemBench expansion is deferred until its supporting messages can be annotated.
